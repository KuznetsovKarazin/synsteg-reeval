# Seed-only receiver: проверка синхронизации

Это отдельный учебный прототип: получатель восстанавливает биты по ключу и
стеготексту, имея заранее общий публичный словарь и код протокола. Исходный
cover и таблица конкретного документа ему не передаются.

**Словарь задан вручную, не сгенерирован ИИ.** Он содержит три небольших
непересекающихся класса по четыре словоформы. Cover намеренно искусственный:
повторы слов с пунктуацией и пробелами. Успешное восстановление проверяет
архитектуру обмена данными; оно не устанавливает пригодность для естественных
текстов, сохранение смысла, незаметность или криптографическую защищённость.

## Запуск

Из корня репозитория, Python 3.12, только стандартная библиотека:

```bash
python experiments/seed_only_receiver_v1/run_proof.py
```

Скрипт заново записывает `proof_result.json` рядом с собой. Все пути вычисляются
от расположения файла. Модели, сеть и данные закрытого эксперимента не нужны.
Скрипт читает прежний `src/synsteg_audit/fixed_codebook.py` для отдельного
контрпримера; исходный код и результаты v3 не изменяются.

Проверяются 12 точных восстановлений: длины 0, 1, 7, 32, 64 и 127 бит, по два
разных выбора слова внутри назначенной битовой группы. Для каждого вызова
получатель запускается новым Python-процессом с `-I -S`, пустым рабочим каталогом
и минимальным окружением. Через stdin разрешены ровно `key_hex` и `stego_text`.
После загрузки публичного кода audit hook запрещает открытия файлов, операции
сокетов и запуск подпроцессов; самопроверки этой политики тоже обязательны.
Это ограничение проверяемой программы, а не защитная песочница операционной системы.

## Что является общими данными

Ключ — единственный секретный вход **предлагаемой архитектуры**. Словарь, версия,
правила токенизации и алгоритм остаются общими публичными данными. В тесте даже
ключи и nonce публичные, детерминированные и явно помечены как fixtures; они
не предназначены для реальной защиты сообщений.

Текст несёт открытый заголовок: 128 бит nonce и 32 бита длины. Это **160 бит
накладных расходов** до полезной нагрузки. Публичная схема заголовка здесь нужна
для проверки отсутствия внешних полей; её статистическая заметность не измерялась.
HMAC-SHA256 с ключом задаёт перестановку слов для полезной нагрузки. Качество слов
не оценивается: два варианта выбора демонстрируют независимость декодера от
выбора отправителя внутри одной группы.

Шифрование и аутентификация отсутствуют. Отрицательные проверки подтверждают:
неверный ключ и подмена слова дают неверные биты **без отказа**. Поэтому результат
нельзя интерпретировать как проверенную защищённую систему. Для следующего
эксперимента нужны отдельный проверенный слой AEAD, правила nonce, проверка
языковых классов, политика повреждений канала и независимая оценка текстов.

## Происхождение контрпримера прежнего кодека

В `run_proof.py` отдельно вызывается настоящий `fixed_codebook.py` из этого
репозитория: 128 повторов `small`, четыре одинаковых кандидата в каждой позиции,
публичный строковый seed `private-seed-example` и 32-битное учебное сообщение.
С оригинальной таблицей восстановление точно. Пересборка таблицы по стеготексту
с тем же seed и кандидатами даёт 14 неверных бит из 32. Хеш исходного модуля
записан в `proof_result.json`; его замороженный исходный коммит —
`674b370c79093f8218adeed09a07bf16f250e143`.

Это новый синтетический контрпример зависимости от оригинального cover.
Он **не является попыткой исходного v3**, повторным открытием его теста или
изменением ранее полученных результатов. Прежний эксперимент использовал общую
таблицу документа; здесь проверяется другой интерфейс получателя.

## Альтернатива с детерминированной нейросетью

Обе стороны могут воспроизводить **сначала исходный cover, затем его таблицу**
из общего prompt, ключа, nonce и полностью зафиксированных модели, tokenizer,
ресурсов, параметров и среды. Потребуется проверить побайтное совпадение.
Просто пересобрать таблицу по изменённому стеготексту недостаточно: это другой
вход. Для произвольного пользовательского cover seed не передаёт его содержимое.

Другой вариант — одинаково генерировать общую, не зависящую от документа
таблицу. В данном прототипе такая генерация не реализована. Подробный разбор
вариантов и точные ссылки на первичные источники — в [assessment_ru.md](assessment_ru.md).

Файлы: `receiver_proof.py` — учебный кодек и процесс получателя;
`run_proof.py` — воспроизводимая проверка; `proof_result.json` — её результаты;
`assessment_ru.md` — технический разбор.
