# Независимая проверка четырёх контекстов: только исходники

Оставшихся блокирующих замечаний к проверенному исходному варианту не обнаружено. Это готовность к регистрации и ограниченному запуску, не результат NN-эксперимента. Проверен helper SHA256 `b97aa4ac71f6a2c6971ae72460d3b65275eff4db1539b34c05e39fb5c32367af`; все 30 файлов объявленного closure совпадают с хешами. Три ключевых старых исходника отдельно считаны из main `5205e2a0e37611d6dd6326cebd45c2c78f0ce90b`; вычисленные Git blob SHA и байты совпали с финальным checkout.

Полный development100 независимо прочитан из Git. Правило первых документов первых четырёх тем даёт 1, 4, 7, 10. Все поля выбранных четырёх строк совпадают, source groups различны. Это не слепая регистрация: предыдущие development-выходы могли быть известны. Test не читался.

Первые синтетические проверки выявили два дефекта: `backend_error` и отсутствующий status не останавливали кампанию. Логи провалов сохранены. После исправлений и дополнительной проверки обработки повреждённого delivery evidence финальная проверка дала **7/7 campaign и 5/5 gate**. Проверены сохранение знаменателей, уникальность восьми key/nonce, запрет повторного выхода, остановка на unknown/backend/missing status/evidence error/worker error, полный синтетический путь 8+4 и отклонение изменённого источника, неполного closure и неверной привязки context ID. Это подменённые операции, модель и tokenizer не запускались.

Получатель стартует через exec с публичной установкой и явными wire/key/envelope/context/spec/profile. Fixture и ожидаемый plaintext ему не передаются; установка остаётся на том же хосте без sandbox, с hardlink ресурсов. Публичный envelope раскрывает arm. Обычный контроль использует тот же keyed transform. Поэтому доставка не будет доказательством скрытности, естественности, фактической верности либо переносимости.

Знаменатели до начала: 4 подготовительных TOKENIZE, 8 генераций, 4 свежих получателя, 12 endpoint и 4 доставки. Внутри endpoints предусмотрены дополнительные TOKENIZE. Перед генерацией root обязан сохранить и перечитать из Git все четыре prompt-ID context; затем нужна отдельная execute activation. Неизвестные исходы сохраняются без повторов. Ключ 32 байта, payload 16 байт, кадр 34 байта, nonce 12 байт; реальные размеры wire, context и envelope надо измерить после запуска.

Повторение проверок: задайте `CONTEXT4_CHECKOUT` абсолютным путём к восстановленному checkout и запустите `check_campaign.py`, затем `check_gate.py` из этой директории. Точные команды и ограничения — в `review.json`.
