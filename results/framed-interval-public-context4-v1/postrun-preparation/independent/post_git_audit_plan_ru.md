# Независимый аудит после сохранения: план до просмотра результатов

План относится к `framed-interval-public-context4-v1`. До получения фактического Git commit результаты и тексты не читаются. Модель, native bridge и tokenizer не запускаются; семантика и фактическая верность текстов остаются отдельному аудитору.

1. Получить SHA трёх стадий: source/tokenization activation; сохранённые prompt IDs/execute activation; результаты. Проверить ancestry и перечитать фактические файлы из этих commit. Сверить все 30 source-closure hashes, helper `b97aa4ac71f6a2c6971ae72460d3b65275eff4db1539b34c05e39fb5c32367af`, обе activation/readback, четыре source/context ID. Отличать наличие proof JSON от независимо подтверждённого Git readback.
2. Восстановить матрицу **12 запланированных endpoints**: восемь sender и четыре receiver. Для каждого раздельно фиксировать reserved/not_attempted, terminal success/known refusal/unknown/dependency_blocked, чистое завершение supervisor и доступность журналов. Основной знаменатель доставки всегда **4**, генераций — **8**. Пропущенный или неизвестный исход не превращается в неуспех известного типа и не исключается. Проверить отсутствие повторных reservations/attempts и остановку оставшихся случаев после первой unknown/integrity failure.
3. Для всех доступных endpoint-журналов независимо проверить цепочку prepare/commit, номера, SHA, committed bytes/IDs/traces, незавершённый native STEP и оборванную строку. Пересчитать integer bins и transitions из сохранённых laws и наблюдённых token IDs; сверить before/after/emitted bits, HMAC ordering, admission и base-law evidence, где они сохранены. Для четырёх пар sender/receiver сравнить общий wire и laws/traces по префиксу. Это аудит сохранённой арифметики и двух независимых исполнений; он не восстанавливает вероятности модели заново.
4. Для каждой заявленной доставки определить первое накопление >=272 emitted bits. Оно обязано совпасть с последним обработанным token, заявленным first_threshold_token и полным wire, при <=768 tokens. Пересобрать первые 272 бита в 34 байта, выполнить только CPU AEAD-decrypt с ключом/envelope, проверить длину 16 байт и **все** байты `000102030405060708090a0b0c0d0e0f`; сверить received-payload.bin и worker result. Подтверждать доставку лишь при чистом supervisor, полном журнале и всех совпадениях. Ordinary не получает payload-delivery статус; его threshold/cap/refusal остаются отдельными исходами.
5. Проверить receiver argv, receiver-inputs и inventory публичной установки: wire/key/public envelope/context/spec/profile; нет payload-file, nonce-ledger, fixture или sender trace во входном контракте. Сверить байты переданного wire с sender commit. Проверить свежий exec и процессы из supervisor/owned-process evidence. Это логическое разделение на одном хосте, не OS sandbox и не межхостовая репликация.
6. Проверить весь сохранённый sender nonce ledger: HMAC reservation ID, пары key/nonce, receipts в каждом sender, burn-before-generation и отсутствие восьми потенциальных коллизий. Число фактических записей зависит от реально начатых sender; неизвестные и отказавшие reservations не удаляются. Проверить наличие полного restore map для 41 named resource, их frozen hashes и runtime/preprompt/resident evidence для каждого вызова. Без загрузки самих бинарных ресурсов аудит подтверждает сохранённые идентичности и полноту пути восстановления, а не новое вычисление их текущих байтов.
7. Посчитать по всем восьми случаям доступные точные размеры wire, envelope JSON и context JSON, отдельно фактический размер файла и canonical transport JSON. Для отсутствующего wire писать null, не ноль. Для доставленного payload отдельно: 16 B полезных данных, 34 B кадра, 18 B overhead; 12 B nonce уже входит в envelope. Показать per-message wire+envelope при заранее известных context/spec и first-context wire+envelope+context+spec. Ключ 32 B, profile/spec, 41 named resources и source/runtime setup — отдельные shared costs; не удваивать nonce и не выдавать сумму по именам/hardlinks за уникальные байты.

Минимальный пакет для одного полного аудита:

- Точные commit SHA стадий и Git tree listing результата; activation/readback пути root передаёт явно.
- `experiments/framed-interval-public-context4-v1/` целиком, плюс все 30 файлов, перечисленные source-closure. Старые публичные spec/profile/entry уже включены в closure.
- `results/framed-interval-public-context4-v1/tokenization/` целиком: initial denominator, reservation/supervisor/resource/resident/context/tokenization и общий contexts JSON, включая ошибки.
- `results/framed-interval-public-context4-v1/generation/` целиком: initial denominator, snapshots, итог, receiver inventory; все `{case}/{sender,receiver}-inputs`, `{sender,receiver}-process` и endpoint outputs. Критичны worker-result, execution-started, token-journal.jsonl, traces.json, committed-wire.bin, wire.raw, received-payload.bin, reconciliation/recovered-status, nonce receipt, native resource/preprompt/owned-process evidence и все crash/error logs. Отсутствующие файлы не синтезировать.
- `runtime/framed-interval-public-context4-v1/sender-nonces/` целиком и точный tree listing. Бинарную receiver-install копию загружать не требуется: inventory плюс frozen source/profile/resource identities достаточны для заявленного ограниченного аудита.
- `results/framed-interval-public-context4-v1/preparation/resource-restore-map.json` и provenance manifests, на которые он ссылается. Архив/модель повторно не загружаются.

Практически три полных Git-поддерева нового опыта плюс nonce ledger безопаснее ручной выборки: перечень имен покрывает ошибки и сохраняет неизвестные исходы. `reconcile()` старого worker пишет файлы; аудитор его на сохранённом evidence не вызывает. Разбор journal и pure arithmetic/AEAD выполняются на отдельной копии, результаты аудита — под новым audit ID без изменения исходных записей. После проверки выдаются JSON с 12 строками endpoint, четыре строки доставки, восемь строк стоимости, перечень ограничений и отдельный вердикт о полноте сохранения.
